# Requirements: Festival Lineup Prompt Evaluator

**Defined:** 2026-01-22
**Core Value:** Accurately measure which combination of system prompt + Claude model produces the most correct festival lineup extractions.

## v1 Requirements

### Test Management

- [x] **TEST-01**: User can add test cases with festival name, image, and ground truth lineup
- [x] **TEST-02**: User can edit existing test cases
- [x] **TEST-03**: User can delete test cases
- [x] **TEST-04**: User can view image preview in test case list

### Prompt Configuration

- [x] **PROMPT-01**: User can paste a custom system prompt
- [x] **PROMPT-02**: User can select which Claude model to use

### Execution

- [x] **EXEC-01**: User can run text-based tests (festival name -> lineup)
- [x] **EXEC-02**: User can run image-based tests (festival image -> lineup)
- [x] **EXEC-03**: User can run batch tests against all test cases

### Evaluation

- [x] **EVAL-01**: System compares results using strict string matching
- [x] **EVAL-02**: System calculates percentage of artists matched per test
- [x] **EVAL-03**: System shows how many tests achieved 100% accuracy

### Results

- [x] **RSLT-01**: User can view results table with expected vs actual output
- [x] **RSLT-02**: User can see pass/fail status for each test
- [x] **RSLT-03**: User can export results as CSV/JSON

### Persistence

- [x] **DATA-01**: Test cases persist between sessions
- [x] **DATA-02**: Images stored locally and referenced by test cases

## v2 Requirements (Deferred)

### History & Tracking

- **HIST-01**: User can view previous test run results
- **HIST-02**: User can compare results across runs

### Advanced Evaluation

- **ADVL-01**: System provides per-artist matching breakdown
- **ADVL-02**: System supports partial credit scoring (fuzzy matching)

### Integration

- **INTG-01**: CLI interface for scriptable access
- **INTG-02**: Cost tracking per test run
- **INTG-03**: Speed/latency tracking per request

## Out of Scope

| Feature | Reason |
|---------|--------|
| Fuzzy matching | User requires strict string comparison for evaluation |
| Production monitoring | This is a testing/iteration tool, not production infrastructure |
| Multi-user collaboration | Single-user developer tool |
| Auto-prompt optimization | Manual iteration workflow preferred |
| LLM-as-judge evaluation | Stick to deterministic string comparison |
| Real-time streaming | Batch testing doesn't need live updates |
| Cloud deployment | Local-first tool |
