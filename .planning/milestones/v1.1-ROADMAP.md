# Milestone v1.1: Web Search Eval

**Status:** SHIPPED 2026-01-29
**Phases:** 5-7
**Total Plans:** 6

## Overview

v1.1 adds web search evaluation alongside the existing image-based eval. Users get a separate tab with independent test cases, prompts, and model selection. The milestone delivers CRUD for web search tests, execution with Claude web search tools, and results display with metrics and export.

## Phases

### Phase 5: UI Foundation

**Goal**: User can access web search eval as a separate workspace with independent configuration
**Depends on**: Phase 4 (v1.0 complete)
**Plans**: 1 plan

Plans:
- [x] 05-01-PLAN.md — Tabbed workspace UI with independent prompt config per workspace

**Details:**
- WorkspaceTabs component with ARIA accessibility
- PromptConfig made workspace-aware with prop-based behavior
- Dual persistence: backend for image-eval, localStorage for web-search-eval
- Active tab persisted in localStorage

### Phase 6: Test Management

**Goal**: User can create, edit, and delete web search test cases that persist
**Depends on**: Phase 5
**Plans**: 2 plans

Plans:
- [x] 06-01-PLAN.md — Web search test case CRUD with localStorage persistence
- [x] 06-02-PLAN.md — Fix navigation paths (gap closure)

**Details:**
- useWebSearchTests hook with full CRUD operations
- Test case structure: id (UUID), name, year (4-digit), lineup (string array)
- localStorage persistence under key 'web-search-eval:test-cases'
- TestCaseList, TestCaseCreate, TestCaseEdit pages
- Routes integrated in App.jsx

### Phase 7: Execution and Results

**Goal**: User can run web search tests and view results with metrics
**Depends on**: Phase 6
**Plans**: 3 plans

Plans:
- [x] 07-01-PLAN.md — Backend API endpoints for web search execution
- [x] 07-02-PLAN.md — Frontend execution hooks and batch progress UI
- [x] 07-03-PLAN.md — Results display with metrics, inline diff, and JSON export

**Details:**
- Backend API with 5 endpoints (single execution, batch start/progress/cancel/results)
- Test data passed in request body (lives in localStorage)
- useWebSearchExecution and useWebSearchBatch hooks
- WebSearchBatchProgress component with cancel button
- Results table with expandable rows showing inline diff
- Aggregate metrics: total, perfect count, average accuracy, failed count
- JSON export with config and summary metadata

## Milestone Summary

**Key Decisions:**

- ARIA tab pattern for workspace switching (accessibility)
- Web search eval uses localStorage only (no backend sync for tests)
- Navigation links only for image-eval workspace (web search has separate routes)
- crypto.randomUUID() for client-side ID generation
- Test data passed in request body (web search tests live in localStorage)
- 100% match = pass, partial shows accuracy percentage
- Inline diff uses green=correct, red=missing, yellow=extra

**Issues Resolved:**

- Route ordering fixed in web_search_executions.py (batch routes above parameterized route)
- Infinite loop in useStickyState fixed with deep equality check
- App.jsx Routes structure consolidated to single block
- Navigation paths fixed in TestCaseCreate and TestCaseEdit

**Issues Deferred:**

- None

**Technical Debt Incurred:**

- Single test result display not wired (onSingleResult prop unused) - batch execution is primary use case
