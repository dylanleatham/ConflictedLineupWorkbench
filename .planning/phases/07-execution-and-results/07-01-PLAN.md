  <action>
Create `backend/api/web_search_executions.py` with endpoints for web search test execution.

**Follow the pattern from `backend/api/executions.py` but adapted for web search tests:**

1. Request/Response models:
   - `WebSearchExecutionRequest`: system_prompt, model
   - `WebSearchExecutionResult`: test_id, status, extracted_lineup, accuracy, error, metadata
   - `WebSearchBatchRequest`: test_ids, system_prompt, model (no mode - web search only)
   - `WebSearchBatchStartResponse`: batch_id, status
   - `WebSearchBatchProgress`: total, completed, failed, cancelled, current_test_id
   - `WebSearchBatchSummary`: total, completed, failed, perfect_count, average_accuracy, results

2. Single test endpoint `POST /api/web-search/executions/{test_id}`:
   - Accept test_id as path param, WebSearchExecutionRequest as body
   - Load test case from localStorage data (tests come from frontend, not backend storage)
   - Actually, tests are stored in localStorage on frontend - so the request body needs to include the test data:
     - Change request to include: festival_name, year, ground_truth_lineup, system_prompt, model
   - Call `extract_lineup_from_text(f"{festival_name} {year}", system_prompt, model)` from claude.py
   - Calculate accuracy using `calculate_accuracy(extracted, ground_truth_lineup)` from evaluator.py
   - Return WebSearchExecutionResult

3. Batch endpoints (same pattern as executions.py):
   - `POST /api/web-search/executions/batch` - Start batch, returns batch_id
   - `GET /api/web-search/executions/batch/{batch_id}/progress` - Get progress
   - `POST /api/web-search/executions/batch/{batch_id}/cancel` - Cancel batch
   - `GET /api/web-search/executions/batch/{batch_id}/results` - Get final results

4. Batch request should include list of test objects:
   ```python
   class WebSearchTestInput(BaseModel):
       id: str
       festival_name: str
       year: str
       ground_truth_lineup: List[str]

   class WebSearchBatchRequest(BaseModel):
       tests: List[WebSearchTestInput]
       system_prompt: str
       model: str
   ```

5. In-memory batch state storage (same as executions.py):
   - `web_search_batch_states: Dict[str, WebSearchBatchState] = {}`
   - Background task with `run_web_search_batch_execution(batch_id, tests)`
   - Flag-based cancellation (check `state.cancelled` before each test)
   - Keep completed results on cancel, remaining tests skipped

6. Register router in `backend/main.py`:
   - Add `from backend.api.web_search_executions import router as web_search_executions_router`
   - Add `app.include_router(web_search_executions_router)`

**Key difference from image-eval execution:**
- No mode parameter (always web search)
- Test data passed in request body (not loaded from backend storage)
- Uses `extract_lineup_from_text` which already has web_search tool configured
